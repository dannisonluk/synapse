# 主題系統

兩套主題：**Light** 與 **Dark**，可在工具列切換，偏好會被記住。

這份文件說明配色安排、字體層級、互動狀態，以及**為什麼是這些顏色**。

---

## 1. 為什麼要重做

舊版有兩個問題，第二個比較嚴重：

1. **配色取向太特殊。** 淺色是暖米色底（`#FDFBF7`）配 Anthropic 陶土橘
   （`#DA5B2A`），深色是 GitHub 藍。兩套主題的**色溫完全不同** ——
   同一個介面在兩種模式下像是兩個產品。而且飽和橘當強調色在資料密集的
   畫面上很刺眼。

2. **配色散在元件裡。** token 只有 11 個，而元件裡有 97 處
   `isLight ? "bg-stone-50" : "bg-slate-900"` 的硬編碼 Tailwind class。
   那等於「配色」實際上有 97 份，而且已經開始分岔了（有些地方淺色用
   `stone`、有些用 `gray`；深色有的 `slate`、有的 `gray-900`）。

現在的做法：**語意 token → CSS 自訂屬性 → 元件不判斷主題**。

```
theme/tokens.ts      兩套主題的數值（唯一真相）
      ↓ cssVariables()
theme/ThemeContext   展開成 --syn-* 掛在最外層
      ↓ var(--syn-…)
theme/ui.ts          常用組合的 class 常數
      ↓
元件                 不寫 isLight，兩套主題共用同一份 class
```

## 2. 配色取向：傳統中性色系

刻意選**最常見**的那一組（白／淺灰＋標準藍、石墨灰＋藍），理由有三：

- 使用者不需要重新學習任何東西
- 對比度是別人已經調過的，不是我們猜的
- 中性色不會跟資料本身的顏色競爭 —— 這是一個看資料的工具，
  介面不該搶戲

**沒有**：暖米色底、紫調底色、霓虹青／紫、高飽和橘。
`tailwind.config.js` 裡原本有一組寫死的 `#00f0ff`（霓虹青）與 `#7000ff`（紫），
實測零使用，已刪除 —— 留著會讓人以為那是專案強調色而拿去用。

## 3. 主要元件的配色安排

### 3.1 背景：三層，兩套主題方向相反

| 層 | 用途 | Light | Dark |
|---|---|---|---|
| `bgCanvas` | 畫布／最底層 | `#FFFFFF` | `#0D1117` |
| `bgPanel` | 面板、抽屜、節點表單分組 | `#F6F8FA` | `#161B22` |
| `bgCard` | 卡片、節點、浮層 | `#FFFFFF` | `#1C2128` |

**方向是相反的**，這是刻意的：

- 淺色：**越上層越白**。卡片是純白，浮在淺灰面板上，用邊框與陰影分離。
- 深色：**越上層越亮**。深色介面不能靠「更白」分層（會刺眼），
  而是靠「稍微提亮」—— 這是深色 UI 的常規做法。

這個差異有一個副作用，而且它是被斷言抓出來的：深色的 `bgCard` 比
`bgCanvas` 亮，所以同一個 `textMuted` 在卡片上的對比度**比較低**。
第一版的 `textMuted` 在卡片上只有 4.34:1，低於 AA。修法是調亮文字，
不是把卡片壓暗 —— 卡片比畫布亮是深色介面的正確行為。

另有 `bgInput`（輸入框）、`bgHover`、`bgActive`（互動狀態）、`bgCode`。

`bgCode` 在**兩套主題下都是深底**：SQL 的語法色是為深底調的，
而且深底能讓「這是唯讀的程式碼，不是可編輯欄位」一眼可辨。

### 3.2 文字：三層，兩套主題同一組比例

| 層 | 用途 | Light | Dark |
|---|---|---|---|
| `textPrimary` | 內文、標題 | `#1F2328` | `#E6EDF3` |
| `textSecondary` | 次要說明 | `#424A53` | `#B1BAC4` |
| `textMuted` | 提示、單位、第三層 | `#656D76` | `#848D97` |

三層的對比度刻意拉開，而且**兩套主題的比例一致**（約 16 : 9 : 5.2）：

```
Light  15.80 : 8.99 : 5.25
Dark   16.02 : 9.63 : 5.62
```

舊版的 `textSecondary`（`#78716C`）只有 4.6:1，而它被用在 10–12px 的說明文字上。
**小字需要的是更高的對比，不是更低** —— 所以現在次要文字也要 ≥ 4.5，
而 `textMuted` 這個最常被當成「不重要」的層級，實際上要求 4.5:1 才過關。

### 3.3 強調色：只有一個，而且只用於「主要動作」與「選取」

| token | 用途 | Light | Dark |
|---|---|---|---|
| `accent` | 主要按鈕底、選取、圖示 | `#0969DA` | `#1F6FEB` |
| `accentHover` | 上述的 hover | `#0550AE` | `#388BFD` |
| `textOnAccent` | accent 底上的文字 | `#FFFFFF` | `#FFFFFF` |
| `accentSoft` | 淡強調底（標籤、選取提示） | `#DDF4FF` | `#12283F` |
| `accentSoftText` | 淡強調底上的文字 | `#0550AE` | `#79C0FF` |

**一張畫布上不該有兩個強調色。** 節點邊線用中性灰（`edgeStroke`）而不是
強調色 —— 一張 20 條線的圖如果全部是飽和藍，節點反而看不清楚。
強調色留給「選中」與「主要動作」。

`accentHover` 在深色主題是**變亮**、淺色是**變暗**：兩邊都是「離底色更遠」，
方向不同但語意一致。

### 3.4 按鈕：三種，階層明確

| 常數 | 用途 | 外觀 |
|---|---|---|
| `ui.btn` | 工具列、次要動作 | 卡片底 + 邊框，hover 換底色 |
| `ui.btnPrimary` | **一頁只有一個**的主要動作 | accent 底 + `textOnAccent` |
| `ui.btnIcon` | 圖示按鈕 | 無邊框，hover 才出現底色 |
| `ui.btnLink` | 連結感的文字按鈕 | accent 文字 + hover 底線 |

三種都有同一組**鍵盤聚焦環**（`ui.focusRing`）：

```css
focus-visible:ring-2 ring-[var(--syn-border-focus)]
```

用 `focus-visible` 而不是 `focus` 是刻意的：滑鼠點擊不該留下一個環，
而鍵盤操作**必須**看得見焦點在哪 —— 那是無障礙的底線，不是裝飾。

### 3.5 語意色

| token | Light | Dark | 對比度（on bgCanvas） |
|---|---|---|---|
| `danger` | `#CF222E` | `#F85149` | 5.36 / 5.65 |
| `success` | `#1A7F37` | `#3FB950` | 5.08 / 7.45 |
| `warning` | `#9A6700` | `#D29922` | 4.87 / 7.50 |

每個都有一個 `*Soft` 版本當底色（`dangerSoft` 等），用於錯誤橫幅。
深色的 `*Soft` 是「低飽和的暗色」而不是「暗色的半透明」——
後者疊在深色底上會變成灰，失去色相。

## 4. 字體層級

四級，刻意收斂。舊版同時存在 9 / 10 / 11 / 12 / 13px 五種尺寸，
而且是隨手挑的 —— 沒有層級就沒有節奏，使用者要靠猜才知道哪個比較重要。

| 常數 | 尺寸 | 用途 |
|---|---|---|
| `TYPE.title` | 13px | 節點標題、面板標題 |
| `TYPE.body` | 12px | 內文、按鈕文字 |
| `TYPE.mono` | 11px | 數值、SQL、識別字 |
| `TYPE.caption` | 10px | 次要說明、單位、提示 |
| `TYPE.label` | 10px | 區塊標籤（全大寫＋字距） |

**9px 退場。** 它在一般 DPI 下低於可讀下限，而它最常被用在「其實很重要的
提示」上 —— 例如「未設定左右鍵 → 這個節點會直接通過」。目前還有 72 處待遷移，
上限已被守門固定住（只可以往下調）。

行高寫進常數：小字配大字距會鬆散、配小行高會擠，這兩件事是一起調的。

## 5. 實測對比度

全部由 `scripts/verify.mjs` 的 §2j 計算並斷言，不是目測。
門檻依 WCAG AA（一般文字 4.5:1、大字與非文字 3:1），
主要文字用 AAA（7:1）。

| 配對 | Light | Dark | 門檻 |
|---|---|---|---|
| `textPrimary` on `bgCanvas` | 15.80:1 | 16.02:1 | 7.0:1 |
| `textSecondary` on `bgCanvas` | 8.99:1 | 9.63:1 | 4.5:1 |
| `textMuted` on `bgCanvas` | 5.25:1 | 5.62:1 | 4.5:1 |
| `textPrimary` on `bgPanel` | 14.84:1 | 14.64:1 | 7.0:1 |
| `textMuted` on `bgCard` | 5.25:1 | 4.81:1 | 4.5:1 |
| `textOnAccent` on `accent` | 5.19:1 | 4.63:1 | 4.5:1 |
| `accentSoftText` on `accentSoft` | 6.68:1 | 7.71:1 | 4.5:1 |
| `accent` on `bgCanvas` | 5.19:1 | 4.08:1 | 3.0:1 |
| `danger` on `bgCanvas` | 5.36:1 | 5.65:1 | 4.5:1 |
| `success` on `bgCanvas` | 5.08:1 | 7.45:1 | 4.5:1 |
| `warning` on `bgCanvas` | 4.87:1 | 7.50:1 | 4.5:1 |
| `border` on `bgCanvas` | 1.45:1 | 1.55:1 | 1.3:1 |

`border` 的門檻只有 1.3 是因為邊框是**分隔**用的，不是拿來看的；
要求它達到 3:1 會讓整個介面變成一堆黑線。

## 6. 切換與持久化

順序是 **存檔優先 → 系統偏好 → 預設淺色**。順序不能顛倒：
使用者手動選過的主題不該被系統設定蓋掉。

- 偏好存在 `synapse.theme.v1`，與自動存檔**分開兩個 key** ——
  清空工作流（New）不該順便把主題選擇也清掉。
- 舊版存的是 `claude-light` / `github-dark`，那些值現在不合法，
  會被當成「沒存過」而退回系統偏好。這是刻意的：寧可退回預設，
  也不要嘗試對應一個已經不存在的配色。
- 切換時會設定 `document.documentElement.style.colorScheme`，
  讓**原生控件**（捲軸、下拉、日期選擇器）跟著主題走。
  沒有這一行，深色主題下會出現亮白捲軸。

## 7. 怎麼加一個顏色

1. 加到 `theme/tokens.ts` 的 `ThemeTokens`，**兩套主題都要給值**。
   守門會斷言兩邊的鍵完全相同 —— 少一邊會讓 `var(--syn-…)` 解析不到，
   而無效值在瀏覽器裡是**靜默**的（退回 inherit），非常難查。
2. 如果是「文字疊在某個底上」的組合，在 `scripts/verify.mjs` 的 §2j
   加一組對比度斷言。
3. 常用的組合再加到 `theme/ui.ts`。
4. **不要**加到 `tailwind.config.js` —— 那裡的顏色不隨主題改變。
